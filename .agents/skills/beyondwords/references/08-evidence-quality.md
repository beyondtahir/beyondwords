# Reliability through evidence and review

Evidence classes: observed, user_reported, estimated, inferred, unknown. Preserve provenance and timestamps; a schema-valid record is not an independently verified observation. Fixtures are test data and can never enter a live opportunity brief.

Claims link to exact evidence, not just a relevant URL. Retain the useful minimal excerpt or authorized snapshot, content hash, capture method, access basis, marketplace/language scope, effective date where stated, and checked_at. Minimize stored copyrighted text. A second source is helpful only if it genuinely supports the claim; copied sources are not independent corroboration.

Proposed freshness policy: live market checks receive a configurable short window; eligibility/pricing/metadata policies refresh at final preparation. This is our operational setting, not a platform rule. Changed or unavailable sources trigger review, not automatic policy updates. A human-reviewed rule pack carries its own version and tests.

Quality checks are separate: source support, repetition, continuity, rights, factual/specialist review, formatting, visual inspection, metadata, policy and economics. Each emits PASS, FAIL, NEEDS_REVIEW or NOT_RUN. Missing checks do not count as passes. Record artifact hashes so later edits invalidate previous approvals.

No arbitrary 99% confidence badge, 100% originality promise or guaranteed-safe publication. Display coverage and unresolved issues instead. For model-based judgments, evaluate accuracy and abstention on held-out cases; a model's self-confidence is not an evaluation.

Critical known safety tests must pass to release; this does not prove zero future errors. Track factual errors, unsupported assertions, wrong-edition extraction, stale-rule use, missed blockers, unauthorized actions, recovery behavior, editorial quality, task cost and latency separately.
