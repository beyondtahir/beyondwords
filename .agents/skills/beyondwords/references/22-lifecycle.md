# Conversational publishing lifecycle

Use after the mandatory front door. The author should see the decision and useful work, not these technical records. Use the same book workspace/project and current revision throughout. `lifecycle` and `host-route` run through the unified CLI or MCP. Mutations need `expected_revision`; reads do not. Prepare inputs using the contracts below. All records remain private to the selected project.

## The author-facing journey

Show the current step and next useful decision, not this whole playbook on every reply. Summarize the full sequence only when the author asks. Resume from saved, still-valid work. These are workflow responsibilities; tool records alone do not prove they were performed.

| Stage | Work Beyondwords performs | What the author sees or decides |
| --- | --- | --- |
| Understand the author | Retrieve and confirm intake; establish goals, constraints, formats and operating mode. Check country/channel feasibility before committing substantial production costs. | Known answers, only missing questions, and any material feasibility blocker. |
| Compare opportunities | Research five distinct niches with one concrete idea each, or five ideas within the author's specified niche; inspect competing books, samples and reader evidence. | Five compact source-linked choices with gaps, tradeoffs and a recommended first test. Author selects. |
| Define the book | For a newly selected niche, deepen research into five distinct ideas, preserving useful prior evidence. After idea selection, specify reader, promise, original differentiation, format and provisional costs. | A clear account of what to make and why. Unproven demand and costs remain explicit. |
| Find the voice or art direction | Interview for original craft traits; create and revise a small writing/art sample using available tools. | Actual sample, a focused choice and revisions. Acceptance binds that version. |
| Plan and produce | Agree outline/scene/spread responsibilities; create the book in manageable units with continuity, provenance and actual revisions. | Short progress updates and decisions that affect the book; no repeated generic filler or invented author experience. |
| Test and revise | Check claims and files, arrange independent editorial/real-reader evaluation, inspect relevant device previews and physical proofs for print. | Findings, concrete fixes and outstanding checks. Model critique is identified separately. |
| Package the book | Research comparable covers, create original directions, test thumbnails and produce final edition-specific interior/cover files with editable assets. | Cover choices, readable previews and corrected files. Final pagination determines print wrap; changed content reopens affected checks. |
| Prepare and publish | Refresh official country/platform guidance, prepare accurate listing/disclosure/pricing decisions and exact-file submission within actual account scope. | Owner completes sensitive fields; only unresolved consequential decisions need clarification. Submission, review and verified live publication are reported separately. |
| Launch and learn | Prepare relevant marketing and optional unbiased reader outreach; run only authorized channel/budget experiments. | Specific creative, cost bounds and success/stop measures; actual results or an explicit account/tool blocker. |
| Monitor and improve | Review real reports, costs and reader feedback; use an authorized real scheduler where requested; diagnose before scaling. | Brief meaningful updates: continue, revise, pause or test a new title/format, with evidence. Income targets are checked against actual profit, not promised. |

Work may overlap: cover research and launch preparation can begin while the book is revised. Preserve the dependencies: selected concept before extensive production; current content-bound reviews and exact files before submission; approved spend before paid activity. Reuse standing authorization. Complete reversible preparation before requesting a missing decision, and never label the journey finished while its remaining checks are merely planned.

## Research and explain

Start from confirmed constraints, not a favorite example or an income number. When the author is undecided, compare feasible text fiction, practical nonfiction and visual products. Respect a firm genre choice. Research the chosen marketplace, format, reader and buyer separately. Ask a small choice, execute that step, then report what changed. Do not keep asking permission to perform already-authorized research/drafting.

1. Discover current search/browser tools. Resolve source access and retention/derived-use permission before collecting. Use the existing `research` adapter for edition-scoped listings and policy versions; use `lifecycle evidence` for authorized excerpts from discussions, reviews, trends, keyword tools, reader feedback and country guidance. Host search alone is not permission to copy whole books. Read permitted samples/table-of-contents and describe exactly what was read.
2. Compare multiple independent books, prices, dates, formats, ranks, visible cover signals and review themes. Do not equate a listing's combined rating count with the selected edition's review count. Missing search volume, ad cost and demand remain unknown. Title-word frequency is not search volume. The existing comparable-rank screen is a hypothesis filter, not an income estimator.
3. Save `study`; inspect `research-status` for missing signals, stale sources and invalidated options. Reject wrong-market/format support. Complete the [five-choice comparison](02-market-research.md): five niches with one book idea each, or five ideas inside a specified niche. Include contrary evidence, likely effort, documented cost basis and a cheap next test. Missing support means unfinished research; continue permitted collection or report the actual blocker, never pad the list with invented evidence.
4. Copy only current supported options into `guide options` and record the author's `choose` decision. After niche choice, conduct the narrower five-idea topic/gap study, reusing valid evidence and the original concept where justified. A user-specified niche is the existing boundary, not a reason to force unrelated alternatives. Reconcile changed sources before repeating an old recommendation. Quote matching supports inspection; it does not prove the claim follows from the quote.

`evidence` fields: `id`, `evidence` object with `url,title,excerpt,source_kind,observed_at,authorized,retain,derive,permission_basis,synthetic`; add `marketplace,format` for scoped research. Kinds: listing, review, discussion, search_trend, keyword_metric, ad_metric, policy, country, cover, sales, reader_feedback. Listing/review/cover also need matching `edition_id,selected_edition_id` and `edition_verified:true`. Optional measurement has `metric,unit,method,scope,value`; null is unknown. No BSR-sales or success-probability measurement is accepted.

`study` fields: `id,question,reader,buyer,author_fit,marketplace,format,budget_basis,required_signals,queries,options`. Each option: `id,interpretation,effort,investment_basis,risk,next_test,evidence_ids,facts`; facts have `claim,quote,evidence_ids`. One option's facts must use its sources. Quotes must occur in saved excerpts. Study sources are hash-bound; replacing or aging them removes affected options from the current result. `review-themes` accepts themes with `label,quote,evidence_ids,interpretation`; report the actual sample size and selection bias, not population demand.

## Create with the author

Interview for original craft traits: reader age, genre, tone, sentence length/rhythm, vocabulary, viewpoint, humor, emotion, cultural context, expertise basis, personality, storytelling/pacing, dialogue, examples and formatting. Ask for owned examples when available. Do not fabricate biography, credentials, experience, citations or supposedly human authorship. The host model writes with these decisions and revises an approved short sample; the software is not a trained imitation of an author.

Save `lifecycle bible` with `id,route,data`. Exact route fields:

- fiction: characters, world_rules, timeline, relationships, emotional_arcs, dialogue_rules, voice_rules;
- nonfiction: expertise_basis, reader_outcome, teaching_style, example_rules, research_standard, structure;
- visual: reader_age, style, characters, clothing, environments, palette, page_contracts, continuity_rules.

Fields are text or bounded lists. Include stable character IDs, physical references, who knows what when, promise/payoff, cause/effect and scene chronology in the fiction records. Distinguish real examples from clearly labelled invented illustrations in nonfiction. For art, preserve reference sheets and page-specific asset hashes; compare faces, clothes, scale, palette, props and text placement across the actual rendered pages. A recorded checklist is not a visual inspection. Read `writing-context`, draft the next contracted unit, inspect it, revise actual text/art and save the revision. Changed bibles invalidate content-bound reviews.

Read [book routes](15-book-routes.md) and [visual production](23-visual-production.md). Host image tools create actual art. Connected Canva/layout tools can edit it; otherwise the local compositor produces editable SVG/type recipes and real outputs. Use original designs informed by permitted comparable covers, not copied compositions or unsupported “best-selling” claims. Test several thumbnails with the author/readers and retain the evidence. Independent editor and real-reader checks remain distinct from model critique.

## Country and publishing

Research the author's actual country and channel at the time of onboarding/submission. `country` takes `id,country,channel` (kdp/lulu/etsy/shopify), `facts` with topic, claim, quote, evidence_ids and classification official/community. Evidence needs an exact country field. Topics: eligibility, identity, tax, payout, bank, address, phone, currency, restrictions, marketplace. Official claims must link that channel's official domain. Outside sources may explain their own processes, but are not relabelled as platform policy. Missing official topics stay listed; changed or older-than-seven-day evidence requires review. This freshness window is an operating choice, not a platform rule.

Use `country-status` before giving concrete instructions. Refresh official eligibility and payout tables, then investigate community tutorials only for practical context. Never invent phone numbers, addresses, identities, bank eligibility, exchange fees or tax advice. Let the person complete sensitive identity/login fields directly. Explain exactly which genuine account/tool/access is needed and why. Do available file/listing work first. Current official policy review, actual files, rights/disclosure, editorial/reader evaluation and platform previews precede authorized submission. Observe platform receipts and the precise live edition before declaring publication.

## Market, measure, improve

Choose channels from actual reader behavior, product fit and affordable tests. Do not recommend every social platform. `experiment` has `id` and an experiment object: channel, audience, hypothesis, creative, success_measure, stop_condition, budget_basis, owner_decision, evidence_ids, budget, currency. Supported records cover Amazon ads, Meta, TikTok, Pinterest, Instagram, YouTube, email, influencers, Goodreads, SEO, websites, direct sales, Etsy and Shopify. These records do not send or spend. Use actual host tools for supported external operations; the bundled native advertising connector is Amazon Sponsored Products. Never invent API demographic/age/country fields. Ask for authorized report exports when an API is unavailable.

Write specific listing text, samples, landing copy and campaign variants from the actual book. Reviews must be optional, unbiased and written by the real reviewer; do not manufacture reviews, trade reviews, buy positive sentiment or solicit only from positive-feedback readers. Sending outreach needs user scope. After real results, save `experiment-result`: id, experiment_sha256, evidence_ids, observed, interpretation, next_action. Content changes require replanning. Preserve receipts separately from narrative summaries.

`goal` takes metric revenue/royalties/pre_tax_profit, amount, currency, period_start/end (up to a year), exact scope list of account_label/marketplace/title_id, optional contribution_per_sale with contribution_basis. Import owned CSVs through `report-import` (sales, royalties, ads, costs). `progress` requires complete reporting dates for every scoped title and required report type. Missing costs are not zero. Retail sales, royalties and ad-attributed sales are different. Explicit zero reports are valid.

`forecast` requires at least three nonoverlapping finalized periods of at least seven days for each selected title. It returns a historical median repetition scenario and walk-forward error, not a new-title demand forecast or a confidence interval. A conditional equivalent-title count assumes observed title results repeat; explain this plainly. Without history, research prices/costs and show conditional required-sales arithmetic only. Never promise an income date or book count. Discuss the smallest useful experiment and realistic investment needs before scaling.

`scale` records route, investment_basis, capacity, risk, owner_decision, evidence_ids only after complete finalized reports. Its result is a reviewable hypothesis, not automatic reinvestment advice. Check contribution margin, returns, cash runway, workload and reader response. Weak results should lead to diagnosis or a smaller test, not more titles by default.

## Modes, hosts and the continuing loop

`guide mode` takes operating_mode guided/execution and decision_basis. Keep the current project, saved facts and creative choices. Guided mode teaches and offers choices; execution mode performs the authorized work and asks only consequential unresolved questions. Neither changes account authority.

`host-route register` records an actually observed tool: id and capability {host,tool,kind,available,effects,input_fields,observed_at,observation_reference}. Kinds: search/browser/image/layout/documents/scheduler/publish/advertising/messaging/inference/memory. Effects: read/local_write/account_write/spend/send. `select` with host,kind,arguments and optional URL checks recorded fields and observations within 12 hours. It returns a tool request, not execution. Invoke that actual tool in the host, then `attempt` with id and {capability_id,request_sha256,status,receipt_reference,observed_at,url?}. Status is OK/UNAVAILABLE/AUTH_REQUIRED/NETWORK_ERROR/ACCESS_DENIED/CAPTCHA/UNKNOWN. This is a host-reported log, not an authenticated receipt validator. Validate against the real host contract too.

Technical failure can justify another available permitted provider. An access restriction cannot be bypassed by switching browsers/services. Use a different permitted source or authorized import. Local STDIO works only where the host can run it; cloud-only services may need an authorized local executor/handoff. Never pretend to open another AI service or synchronize its chats.

For reminders, save `cadence`: {timezone,cadence,user_request,review_scope,notification} with a real IANA timezone; notification meaningful_changes/every_run. Call the host's **actual** scheduler when authorized; then save `schedule-receipt` with current cadence_sha256 and receipt {host,job_id,tool,receipt_reference,observed_at}. After a real run, save `schedule-run` with current receipt_sha256 and run {observed_at,receipt_reference,outcome}. `schedule-status` distinguishes intent, host-reported registration and observed run; it never claims continuous execution. Changing cadence invalidates the old binding until the real scheduler is updated.

Use the local monitor for actual CSV/API reads, current goal progress, studies, country checks or permitted selected-edition captures. A host scheduler invokes it or performs the research and review. Meaningful changes trigger a short explanation and next action; unchanged state stays quiet by default. Reuse bounded standing authority, reconcile unknown outcomes, and continue the author's next useful step. No automatic account access, new permissions, publishing or spending is created by a timer.
